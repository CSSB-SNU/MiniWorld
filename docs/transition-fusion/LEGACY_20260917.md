## 새 residual 융합 옵션

`transition_residual_fusion=True`로 Triton squeeze+residual FWD와 LN+residual BWD를 선택할 수 있다. 기본값은 True다. **[구현·실측·사용법](RESIDUAL.md)** · [융합 전후 SVG](../../tmp_kernel/transition/TRANSITION_RESIDUAL.svg). 아래 A/B/C/D 표는 `transition_residual_fusion=False`인 기존 경로 기준이다.

## 수식과 범위

```text
xn = LayerNorm(x)
a = xn @ Wa.T; b = xn @ Wb.T
h = SiLU(a) * b
z = h @ Ws.T
y = x + z
```

`D`는 입력 폭, `N=nD`는 확장 폭, `M`은 flatten 후 행 수다. Pair `[B,L,L,D]`는 `M=B·L²`, token `[B,L,D]`는 `M=B·L`이다. **이 모듈에는 mask 인자와 dropout이 없다.** Residual은 항상 적용된다. 커널의 tail 처리를 위한 경계 mask는 모델의 pair/token mask와 다른 개념이다.

실선 상자는 명시한 단일 커널의 융합 경계, 보라색은 cuBLAS 호출, 회색 점선은 여러 커널이 될 수 있는 PyTorch/compiler 연산, 노랑은 HBM tensor다. cuBLAS 호출 하나의 내부 launch 수를 단정하지 않는다. 주요 데이터 의존성을 그렸으며 모든 weight/저장 tensor 입력 화살표, cast, buffer 초기화, 설정 탐색 등을 펼친 전체 launch 목록은 아니다.

## 현재 선택 규칙

모델 생성 전에 `settings.configure(engine_backend="triton")`를 적용하면 일반 Transition은 **A: LN + split SwiGLU + squeeze + residual**을 쓴다. 라이브러리 GEMM은 계속 cuBLAS를 사용한다. `implementation="triton"`만 주고 `engine_backend="auto"`를 유지하면 아래 H100 전용 경로도 선택할 수 있다.

`self.training and torch.is_grad_enabled()`가 학습 분기 조건이다. 안전한 추론 호출은 `eval()`과 `no_grad()`/`inference_mode()`를 함께 사용하는 것이다. `eval()`만으로 autograd나 내부 custom Function의 저장·준비 작업 전체가 꺼지는 것은 아니다. 명시적인 `implementation="cute"`는 이 자동 학습/추론 선택을 거치지 않고 C 계열을 호출한다.

H100 auto, BF16, 기본 옵션, native 빌드가 정상인 대표 shape:

| D | 추론 forward | 학습 forward | 학습 backward |
|---:|---|---|---|
| 128 | B: hand-CUDA b2b | B: hand-CUDA b2b | Triton stacked gate backward + CUDA LN |
| 256 | B: hand-CUDA b2b | B: hand-CUDA b2b | CUDA stacked gate backward + CUDA LN |
| 384 | C: CuTe expand + cuBLAS squeeze + add | D: Triton ktiled b2b + add | Triton stacked gate backward + CUDA LN |
| 512 | C: CuTe expand + 조건부 CuTe squeeze/residual | 동일 | Triton separate dA/dB + CUDA LN |
| 768 | C: CuTe expand + cuBLAS squeeze + add | 동일 | Triton separate dA/dB + Triton LN |

조건:

- B는 `D∈{128,256}`, BF16, `n=4`, `M%128==0`, `transition_cuda_b2b=True`일 때다. 불충족이면 D128은 Triton b2b, D256 추론은 C, D256 학습은 D로 간다. 학습 `_fused_fwd`의 CUDA 빌드/실행 실패에는 Triton expand → cuBLAS squeeze → residual fallback이 있다. 직접 CUDA 추론 wrapper에는 같은 try/fallback이 없다.
- CUDA gate backward는 `transition_gatebwd_wgmma=True`, D256/512, BF16, `M%128==0`, `has_xn=False` 조건이다. 기본 모듈의 D512는 앞서 C로 분기하므로 이 gate에 도달하지 않는다. 실패 시 Triton stacked 재계산으로 간다.
- CuTe squeeze/residual은 weight `[512,2048]`, `M≥16384`, `M%128==0`, contiguous BF16 residual, sm90일 때다. 다른 shape는 cuBLAS squeeze와 별도 residual add다.
- `_transition_ln_bwd`의 CUDA 경로는 `transition_lnbwd_cuda=True`, D≤512, FP16/BF16, affine dtype=입력 dtype, contiguous 입력/gradient 조건이다. `mean=c1/rstd` 복원이 별도이고, native LN backward 자체도 **main + parameter-gradient reduce 두 커널**이다. 실패/조건 불충족 시 Triton 커널을 사용한다. 기본 privatization은 64 replicas이며 최종 dγ/dβ sum 두 호출이 남는다.
- A 정책의 LN backward는 `layer_norm_bwd_dx_fused`이며 input dx와 affine gradient atomic reduction을 수행한다. residual gradient 합산은 그 커널 밖이다.

## 융합 범위와 저장값

### A: Triton 정책

Forward는 `layer_norm_fwd_fused` → `transition_fwd_kernel`(expand 두 GEMM + SwiGLU) → cuBLAS squeeze → residual add다. `xn[M,D]`, `h[M,N]`, `z[M,D]`가 각 경계에서 HBM에 기록된다. 학습은 xn을 보관하지만 h는 backward용으로 보관하지 않는다.

Backward는 dh GEMM → `_transition_expand_gatebwd_savedxn_stacked` → dWs GEMM / dWab GEMM / dxn GEMM → LN backward → residual gradient 합산이다. Gate backward 한 커널이 a/b/h를 재계산하고 dAB를 packed store한다. **GEMM 호출은 4회**다. `[Wa; Wb]`의 weight cat은 별도 준비 작업이다.

### B / D: fused forward + 재계산 backward

B는 통계 pass 다음 hand-CUDA `transition_b2b_rs_wgmma_kernel` 하나가 normalization, 두 expand, SwiGLU, squeeze, residual을 묶는다. xn/h 전체 activation tensor가 forward에서 HBM으로 나가지 않는다.

D≤128의 Triton `_transition_b2b_kernel`도 residual을 포함한다. D>128의 `_transition_b2b_ktiled_kernel`은 squeeze까지 포함하고 residual add는 별도다. 기본 통계 pass는 따로 있다.

학습은 x와 stats를 저장하고 backward에서 xn/h를 재계산한다. 기본 stacked 경로는 dh/dWs/dWab/dxn의 **GEMM 4회**와 gate 재계산 커널, LN backward, residual add로 구성된다. B2는 D256 조건에서 CUDA, 나머지 대표 shape에서는 Triton이다.

### C: CuTe forward + 기본 Triton backward

통계 pass와 `_fold_kernel`은 별도다. Fold는 γ를 weight에 반영하고 S/B2 보정값을 만든다. `GemmLnGatedSm90`은 raw x의 GEMM 결과에 `q*rstd-c1*S+B2` 보정을 적용하고 SwiGLU까지 계산한다. h는 HBM에 기록되며, 뒤의 squeeze와는 별도 커널이다.

모듈은 `prefolded`를 넘기지 않으므로 현재 추론도 weight fold를 호출한다. 학습은 h/xn을 저장하지 않고 backward에서 재계산한다.

기본 `backward_backend="triton"`은 xn 재계산 커널 → dh GEMM → separate dA/dB gate backward → dWs/dWa/dWb 및 dA@Wa/dB@Wb → gradient add → LN backward다. **GEMM 6회**이며 stacked A/B 경로보다 두 호출이 많다. 연산 수만으로 실제 성능을 단정하지 않으며, 다음 점검 대상이다.

## 기본 배선 밖의 옵션

| 설정 / API | 기본값 | 의미 |
|---|---|---|
| `transition_force_split` | False | `_old_triton_forward` 강제; `engine_backend=triton`과 LN backend까지 항상 같은 것은 아님 |
| `transition_cuda_b2b` | True | B 사용 가능 조건 제어 |
| `transition_fuse_stats` | False | 작은 Triton b2b의 stats까지 같은 커널에 포함하는 선택 |
| `transition_large_d_training` | None | 큰 D의 C backward 선택; 실제 함수는 None이면 `triton` 사용 |
| `transition_cute_backward` | `triton` | explicit cute 경로의 backward 선택 |
| `transition_gatebwd_wgmma` | True | fused training의 D256/512 CUDA gate backward 선택 |
| `transition_dab_lnbwd` | False | dAB GEMM + LN dx 융합 실험. parameter gradients와 residual은 밖에 남음 |
| `transition_savedxn_split_bwd` | False | saved-xn API에서 과거 separate backward 비교용 |
| `save_xn=True` API | 모듈 기본 False | fused API의 별도 저장 정책; 기본 모듈 배선과 구분 |

CuTe backward를 명시 선택하면 dh 복제/weight 준비 + CuTe gate backward + stacked GEMM을 사용한다. 이 경로와 B/D의 hand-CUDA gate backward는 별개다.
