# v1.1 준비: distogram 수정과 interchain 가중치

2026-09-16. v1.1 계획 중 **distogram 수정·interchain 가중치와 pair-focus cropping 변경을 구현**했다.
EMA 등 나머지 수정은 후속 작업이다. 패키지 전체를 완성된 v1.1 릴리스로 표시하지 않는다.

## 1. 대표 원자 선택 수정

| Token 종류 | 수정된 대표 원자 |
| --- | --- |
| 표준 단백질, GLY 제외 | CB |
| GLY | CA |
| A / G / DA / DG | 염기의 C4 — 당의 C4′ 아님 |
| C / U / DC / DT | 염기의 C2 — 당의 C2′ 아님 |
| 리간드·비표준 잔기, 기본 atom tokenizer | 각 token에 속한 원자 자체 |

표준 polymer의 지정 원자가 없거나 관측되지 않으면 그 token의 distogram
pair를 제외한다. CB가 없는 ALA를 CA로 대체하거나, 핵산에서 모든 원자를
대표로 표시하던 fallback을 제거했다. 기존 단일 구조 거리 경로는 다중 대표
마스크에서 최저 atom index를 골랐으므로, 핵산의 target이 원자 순서에 따라
달라질 수 있었다. 새 feature는 token당 최대 하나만 표시한다.

원자 규칙은 [AlphaFold 3의 공식 pseudo-beta 정의](https://github.com/google-deepmind/alphafold3/blob/main/src/alphafold3/model/protein_data_processing.py#L78)와
대조했다. 단일 atom token인 리간드 처리는 [공식 scoring 코드](https://github.com/google-deepmind/alphafold3/blob/main/src/alphafold3/model/scoring/scoring.py)의
단일 원자 선택과 일치한다. 기본이 아닌 grouped noncanonical fragment에는
이름 순 첫 원자를 하나 선택하는 명시적 규칙을 둔다; 이를 AF3 atom token과
같은 구성이라고 주장하지 않는다.

거리 계산에서도 NaN/Inf 좌표와 범위를 벗어난 token index를 제외한다.
대표 원자가 필요한 학습 설정에서 feature가 누락되면 조용히 shortest-distance
target으로 전환하지 않고 오류를 낸다. 다중 구조의 대표 원자 경로는 각 구조에서
유효한 pair를 먼저 계산한 뒤 최소 거리를 취한다. 서로 다른 구조에 따로 존재하는
원자를 유효한 pair로 잘못 간주하지 않으며 padding 크기는 logits 기준으로 유지한다.

96 bins, 기존 [2.25, 25.75] Å 경계, overflow bin, i<j reduction은 유지한다.
`atom_is_rep`를 쓰는 confidence target도 같은 수정된 feature를 받는다.
모델 파라미터·checkpoint 모양은 바뀌지 않는다. 다만 이 코드를 사용하는 기존
CB-target 설정도 수정된 정답 정의를 사용하므로 이전 loss와 무조건 동일하지 않다.

## 2. Interchain weight = 2.0

```text
valid(i,j) = i < j AND 두 대표 원자의 좌표가 유효함
w(i,j) = 1                 if asym_id[i] == asym_id[j]
         interchain_weight otherwise

loss = sum(valid * w * pair_cross_entropy) / max(sum(valid), 1)
```

- 분모는 **가중치 합이 아닌 유효 pair 수**다. 다른 chain pair의 loss와
  gradient 기여만 정확히 2배가 된다. 동일 chain 기여는 유지한다.
- chain 판정은 `scheme.token_asym_id`를 사용한다. 동일 서열/동일 entity인
  homomer의 서로 다른 chain도 interchain이다.
- Padding, diagonal, 좌표가 없는 pair는 가중치와 무관하게 제외한다.
- 기본 API 가중치는 1.0이다. v1.1 phase 1a/1b 설정이 2.0을 명시한다.
- Fabric/compile trainer와 별도 manual CUDA-graph trainer 모두 연결했다.

### 새 설정

- `configs/miniworld/phase1a_distogram_v110.yaml`: L384, 기존 1a 구성 + weight 2.0.
- `configs/miniworld/phase1b_distogram_v110.yaml`: L768, 기존 1b 구성 + weight 2.0.
- 새 run 경로는 `runs/v1.1.0/phase1{a,b}/...`다.
- 두 설정은 `data.crop.ab_ag_interface_only=true`, `prefer_nonprotein_focus=true`를
  활성화한다. 예전 설정의 두 옵션 기본값은 false다. EMA 수정은 아직 남아 있다.

## v1.1 cropping

**[전체 그림](../tmp_kernel/cropping/CROPPING.svg)** · [그림 원본](cropping-current.dot)

실제 경로는 `Preprocessor.get_crop_indices` → `crop_spatial_segment_token`이다.

1. 샘플의 chain 1개 또는 chain pair를 읽는다.
2. Pair의 분자 종류에 따라 아래 정책으로 focus 후보를 잡는다. Interface 후보는
   원자 간 6 Å 이내에 접촉하는 잔기의 모든 원자다.
3. 후보의 **유효 원자 하나**를 균등 추출하고, segment 크기를 정수 1~41에서
   뽑은 뒤 전체 assembly를 token화한다.
4. Focus까지의 **최소 원자 거리** 순서로 잔기를 방문한다. 해당 chain의 양쪽
   연속 segment를 추가한다. `cif_idx` 번호 span으로 제한하므로 실제 잔기 수가
   뽑은 segment 크기와 정확히 일치하지 않을 수 있다.
5. Token/atom 예산을 넘는 segment를 만나면 **즉시 break**한다. 잘라 넣기나
   다음 작은 후보로 넘어가기 없이 종료하므로 예산보다 작은 crop이 나올 수 있다.
6. 선택 잔기를 추출하고 OXT/OP3 및 atomless token을 제거한다. MSA/template
   로딩과 feature 구성 뒤 token/atom/MSA/template padding을 적용한다.

H100 기본: L384/4096 atoms 또는 L768/8192 atoms, 최대 MSA depth 2048, template 4.

| Pair 종류 | Chain 중심 분기 | Interface 중심 분기 |
| --- | --- | --- |
| Ab–Ag: 항체 + 단백질 | 없음 | 100% |
| 일반 PPI | 50%: 두 chain 중 균등 선택 | 50% |
| Protein–비protein | 50%: 반드시 비protein 선택 | 50% |
| 비protein–비protein | 50%: 두 chain 중 균등 선택 | 50% |

분자 종류는 로드한 CIF chain의 `seq_id` 첫 글자로 판정한다. A는 항체,
P/Q는 L/D 단백질이며 이 셋을 protein으로 취급한다. 비protein은 R/D/N
(핵산), L(리간드), B(분지형 당), X(기존 ligand 처리 대상)다. A+A는
항체–항체 PPI로 취급한다. Chain 입력 순서는 선택 정책에 영향을 주지 않는다.

Ab–Ag에 접촉이 없으면 `WrongCroppingError`로 실패하며, 기존 dataloader가
다른 항목을 균등 재추출한다. 다른 pair는 기존처럼 chain 중심으로 fallback하지만,
protein–비protein이면 이때도 비protein을 선택한다. Single-chain 샘플은 기존과 같다.

Focus의 chain만 유지하는 crop이 아니므로 제3의 chain도 포함될 수 있다.
Interface focus가 양 chain 보존을 보장하지도 않는다. 미해결 잔기는 segment
확장 과정에서 포함될 수 있으며 좌표 target에서는 mask로 제외된다.

`data/pipeline/crop.py`의 별도 `Cropper` 확률 분기는 이 경로에서 사용되지 않는다.
`CropConfig.monomer_only`와 `remain_invalid_tokens` 역시 위 실제 cropping 함수에
전달되지 않는다. 이번 변경은 focus 후보 선택에 적용되며 이후 공간 crop과 예산 처리는 같다.
