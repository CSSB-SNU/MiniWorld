# v2.0.0 DiT: BiasOnlyTokenDiT + full-bf16 diffusion module

2026-09-18. Phase-2 (diffusion) changes only; the trunk is untouched. Parameter names
change (no q/k in the token DiT), so v2.0.0 starts phase 2a fresh on a v1.x/v1.2 trunk.

## What changed

1. **Token DiT attention = pair bias only** (`src/miniworld/modules/bias_only_token_dit.py`,
   selected by `model.diffusion.token_dit_kind: bias_only`). Per block:
   `p = softmax(to_bias(ln_pair(pair)))` (own `ln_pair`/`to_bias` per block, as in v1 / AF3),
   `out = p @ to_value(AdaLN(single, cond))`, then the v1 value gate, `to_out`, and the
   conditioned output scale; engine `ConditionedTransition` and the plain residuals are
   unchanged. `to_query`/`to_key`/QK-norm are gone, and because `p` does not depend on
   `single` it is computed once per block and broadcast over the augmentations instead of
   once per augmentation. Initialisation matches the v1 block layer by layer.
2. **Full bf16 diffusion module** (`model.diffusion.dtype: bf16`): token DiT, atom DiTs and
   conditioning run with bf16 parameters and activations, no autocast. Norm affine
   parameters stay fp32 (engine `LayerNorm`/`RMSNorm` pin them; engine `AdaptiveLayerNorm`
   now too -- `patches/miniworld-engine-adaln-fp32-norm.patch`), the attention softmax is
   taken in fp32, the RelPos embedder stays fp32, and the denoised update is returned in
   fp32 so the EDM loss and the sampler are unchanged. v1 ran the module in fp32 (Fabric
   `32-true`, TF32 GEMMs); the trunk was already bf16.

Configs: `configs/miniworld/phase2{a,b}_diffusion_v200.yaml` (= v1.0.1 recipe + both switches).

## Measured (H100, 1 GPU, augment 48, fwd+bwd, `runs/prof_v200_full/`)

Full `diffusion_forward` on a real batch, Fabric 32-true for both (production setting):

| | phase 2a (L384/4096 atoms) | phase 2b (L768/8192 atoms) |
| --- | ---: | ---: |
| v1 production (augmented, fp32) | 0.404 s | 0.910 s |
| **v2.0.0** (bias-only + bf16) | **0.209 s** | **0.376 s** |
| speedup | **1.93x** | **2.42x** |

Parts (eager, seconds): token DiT 0.291 -> 0.156 (2a), 0.677 -> 0.252 (2b); atom DiT
enc+dec 0.092 -> 0.050, 0.177 -> 0.093; conditioning 0.011 -> 0.006, 0.033 -> 0.014.
torch.compile changes nothing measurable on top (engine kernels are already fused).

Token DiT alone (`scripts/bench_token_dit.py`, `bench_L*.json`), isolating the two changes:

| L768, fwd+bwd | time | peak |
| --- | ---: | ---: |
| v1 production fp32 | 0.675 s | 9.8 GiB |
| v1 + bf16 autocast only | 0.415 | 9.1 |
| v1 full bf16 | 0.375 | 7.7 |
| v2 bias-only, fp32 | 0.461 | 7.3 |
| **v2 bias-only + full bf16** | **0.252** | **4.5 GiB** |

Structure alone -32%, bf16 alone -44%, together -63% (L384: -46%). The remaining
token-DiT cost is ~60% `ConditionedTransition` (SwiGLU x4) -- the next lever if more is
wanted (`transition expansion 4 -> 2`, or 24 -> 12 blocks as ESMFold2).

## Validation

- `tests/test_bias_only_token_dit.py` (7): shapes, masked softmax, per-block `to_bias`
  called once per forward, no q/k parameters, gradients everywhere, checkpoint parity,
  augment-sharing of the pattern, config switch default `augmented`.
- `tests/test_diffusion_bf16.py` (5): after `.to(bf16)` every norm affine param is fp32 and
  everything else bf16 (by module type), AdaLN `ln_cond` fp32, BiasOnlyTokenDiT bf16
  fwd/bwd finite with fp32 softmax, full `DiffusionModule` bf16 forward on both the AF3 and
  the SWA atom path, v2.0.0 configs compose.
- Not yet: any training run. The first v2 GPU attempt failed on an fp32 one-hot inside the
  RelPos embedder (kept fp32 now); the CPU end-to-end smokes were added so such dtype seams
  are caught before a GPU job.

Known, pre-existing: `tests/test_inference_equivalence.py::test_diffusion_step_matches_canonical`
fails on CPU in the v1.1 tree as well -- the engine `Transition` is hard-wired to bf16 and its
torch fallback path does not cast fp32 activations. The GPU (fused) path is unaffected.
