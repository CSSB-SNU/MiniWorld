샘플링만** 바꾼다. AF3가 MSA를 뽑는 두 지점을 그대로 따른다. 모델 파라미터·checkpoint
레이아웃은 v1.1과 같다.

| 단계 | AF3 | v1.1 | **v1.2.0** |
| --- | --- | --- | --- |
| 데이터: 풀 만들기 (SI 2.2) | main MSA 전체 깊이 n에서 k ~ U[1, n], 섯은 뒤 16,384로 crop | k ~ U[1, min(n, 2048)], **첫 k행** (prefix) | pdb: k ~ U[1, n_full], chain별 무작위 crop → **8192행 풀**. distillation: 변경 없음 (저장소가 2048행 상한) |

## 1. 모델 단계 — recycle별 1024행 재추출

`MiniSWAModel.TrunkConfig.msa_subsample_per_recycle: int | None` (기본 None = 기존 동작).
설정되면:

- `_embed()`는 MSA를 임베딩하지 않고 **raw `MSAFeatures` 풀**을 recycle 루프에 넘긴다.
- `_trunk_step()` 첫 줄의 `_msa_for_step()`가 `subsample_msa_rows(pool, 1024)` →
  `init_msa()`를 수행한다. **MSA 모듈은 매 cycle 1024행만** 본다.
- `DiffusionModel._condition_impl`은 같은 `_embed`/`_trunk_step`을 쓰므로 phase 2 트렁크도
  설정만 켜면 같은 동작이다. 예전 설정(knob 없음)은 그대로다.

`subsample_msa_rows` (`modules/msa_util.py`)의 규칙:

- 출력 깊이는 항상 `min(1024, N_pool)` — `compile(dynamic=False)`·CUDA-graph 캡처가 보는
  shape이 고정된다. `torch._dynamo.explain`: 1 graph, 0 break; `fullgraph=True` 컴파일 통과.
- 난수는 `torch.rand` (기본 CUDA generator). graph replay마다 philox offset이 전진하므로
  replay마다 새 행이 뽑힌다 — dropout과 같은 메커니즘이며 학습 A/B에서 실측으로 확인했다.
- **유효 행(mask) 우선**: 풀이 큰 bucket으로 padding돼 있어도 실제 homolog를 먼저 다 쓰고
  그 뒤에야 padding 행이 들어온다.
- query(0행)는 항상 유지, 뽑힌 행은 원래 best-first 순서를 지킨다.
- `profile`/`deletion_mean`은 전체 alignment 통계라 그대로 통과한다 (AF3와 같음).

부수 효과: MSA 모듈 연산이 풀 크기와 무관하게 1024행 기준이 된다. v1.1(2048행 임베딩
1회 → n_recycle회 재사용)에 비해 cycle당 MSA 모듈 비용은 절반, 원핫 텐서도 1024행분만
만든다. 풀을 8192로 키운 비용은 정수 텐서의 H2D 전송뿐이다.

## 2. 데이터 단계 — pdb 풀을 AF3처럼

`sample_msa(..., sample_depth="af3")`:

```text
n      = 저장된 전체 stack 깊이 (no_pairing: 가장 깊은 chain의 행 수; pdb 저장소는 최대 16,000)
k      ~ Uniform[1, n]
rows   = min(k, pool)                          # pool = MSAConfig.depth_for(source)
행 선택 = ComplexMSA._subsample_no_pairing(rows)  # chain별 무작위 비복원, query 고정, best-first 유지
```

source별 분기는 `MSAConfig.sample_depth_by_source` / `max_msa_depth_by_source`
(`policy_for(source)`, `depth_for(source)`; `Preprocessor._sample_msa`):

| source | 저장 상한 | 정책 | 풀 |
| --- | ---: | --- | ---: |
| `pdb` | 16,000 (300개 표본: median 3,563, **88%가 2,048 초과**) | **af3** | **8192** |
| `protein_monomer`, `short_protein_monomer`, `disordered_pdb` | 2,048 | uniform (불변) | 2048 (불변) |

pdb 풀 8192의 근거: 우리 `no_pairing` stack은 AF3의 **unpaired** MSA에 해당하고, AF3
예산 16,384 중 paired 8,191을 뺀 unpaired 몫이 ~8,192다. 16,384로 올리는 것은
`max_msa_depth_by_source.pdb`와 `bucket_msa_multiple` 두 줄이다.

`train.bucket_msa_multiple`은 가장 큰 풀을 덮어야 하므로 v1.2 설정에서 8192다. 2048행
풀(distillation)은 8192로 padding되고(mask 0), 위 1번의 유효행 우선 규칙이 padding을
걸러낸다. 추론(`data/inference/build.py`)은 `"fixed"`/`"random"` 풀 2048 그대로이며,
모델 knob이 켜져 있으면 추론에서도 recycle마다 1024행을 새로 뽑는다 (AF3/OpenFold3와 같음).
