# preprocessed_CCD_20260826.lmdb

`/public_data/bsoohyuncd/preprocessed_CCD_20260826.lmdb` — 49,426 keys, ~165 MB.
Backup of the pre-stereo state: `preprocessed_CCD_20260826.lmdb.pre-ez.bak`.

Covers every chemical component referenced by `BioMolDB_20260224/cif.lmdb`:
44,590 records carried over from `preprocessed_CCD.lmdb` plus 4,836 that were
missing. Only `UNL` (no `_chem_comp_atom` table in the CCD) and `D8U`
(deuterium(1+), no heavy atoms) are absent — both unrepresentable in this format,
and the original `build_lmdb.py` skipped `UNL` too.

## How stereochemistry is decided

Per centre, not per record:

| situation | decided by |
|---|---|
| coordinates present at the centre | geometry (`AssignStereochemistryFrom3D`) |
| coordinates present, RDKit abstains on a double bond | geometry — direct dihedral |
| coordinates absent, CCD states R/S or E/Z | the CCD label |
| coordinates absent, CCD says `N` | left unspecified |
| coordinates present, geometry finds nothing, CCD states R/S | left unspecified |

Coordinates are the record's own `model_Cartn`, so a stereo call can be
re-derived from the same record. Gaps are handled per atom: a missing `OXT`
does not disqualify a stereocentre elsewhere in the molecule.

### Why the label cannot simply be assigned

The CCD stores **CIP** letters; RDKit stores an **order-relative** tag
(`CHI_TETRAHEDRAL_CW/CCW`) defined by the sequence bonds were added. They
coincide only when the CCD's bond order happens to be an even permutation of
CIP priority order — otherwise the letter inverts. Demonstrable on one molecule:

    bonds added (F,Cl,Br)  tag=CW -> CIP = S
    bonds added (Br,Cl,F)  tag=CW -> CIP = R

The upstream pipeline does exactly this, in
`Ligand-Tokenizer/src/ligand_tokenizer/io/_preprocess_instr.py`:

    CHIRAL_MAP = {"R": CHI_TETRAHEDRAL_CW, "S": CHI_TETRAHEDRAL_CCW}

so per centre it is a coin flip. Measured against RCSB, chiral records went from
**28% correct to 92%** once stereo was taken from coordinates instead. The CCD
labels themselves were never the problem — they agree with the geometry 99.16%
of the time. **This bug is still live in `Ligand-Tokenizer` and affects anything
built from the original `preprocessed_CCD.lmdb`, including `fp_emb_table.pt`.**

Where coordinates are absent the label is honoured by solving for the tag: set
one, read `Chem.AssignCIPLabels` back, flip if it disagrees.

## Reproducing the database

Libraries (imported, no entry point): `mmcif_min.py`, `biomol_codec.py`,
`gen_record.py`, `audit_stereo_from_coords.py`.

    1. parse_ccd.py         components.cif.gz            -> ccd_store.pkl
    2. scan_comp_ids.py     BioMolDB_20260224/cif/raw/*  -> comp_ids.json
    3. build_new_lmdb.py    + missing_ids.json           -> the 49,426-key base
    4. update_changed_coords.py + coords_changed_vs_ccd.json
                                                         -> refreshes 20 records' model_xyz
    5. regen_smiles_final.py --widen                     -> the rdkit_smiles

Step 5 must run last: it regenerates every SMILES from the record, so it has to
see step 4's refreshed coordinates.

## Example CIFs

`dump_cif_from_smiles.py` and `dump_atom_attribution_examples.py`, with
`cif_writer.py` and `stereo_provenance.py`.

    python dump_atom_attribution_examples.py --n 2 --out examples_atom_attribution

Files are built **entirely from `residues.nodes.rdkit_smiles`** — atom table,
bond table, and coordinates generated by RDKit ETKDGv3 + MMFF (seeded). Nothing
comes from `model_Cartn`. The only record contribution is atom *names*, matched
by canonical rank, because a SMILES has none and without them the files cannot
be compared to anything.

Each file carries three blocks beyond the standard categories:

- `_miniworld_source` — provenance, including
  `generated_geometry_reproduces_smiles_stereo`, which re-reads stereo out of the
  generated conformer and checks it against the SMILES
- `_miniworld_smiles_vs_record` — per atom and per bond, SMILES vs record, with
  agreement flags. Aromatic rings compare as `AROM/AROM` rather than by Kekulé
  order, since RDKit picks its own resonance form when re-kekulizing
- `_miniworld_stereo_provenance` — which source decided each centre

`examples_atom_attribution/` holds two examples of each atom-attribution case,
with the case in the filename.

## State as verified

Full-database checks, all 49,426 records:

- every stored SMILES equals what the pipeline produces — **0 out of sync**
- every stereocentre attributable to the rule — **0 violations**
- 82,836 atom centres from geometry, 382 from the label (99.5% geometry)
- 841 atom sites and 422 bond sites where a CCD label was discarded because
  coordinates were available and geometry found no stereocentre
- 220 SMILES RDKit cannot parse (metal clusters; the original had 225)
- 0 non-tetrahedral `@TB`/`@OH`/`@SP` descriptors

The scripts that produced these numbers (`verify_rule.py`, `verify_final.py`,
`validate.py`, `show_stereo.py`) have been removed as requested; the results are
recorded here.

## Known limitations

- **The CCD snapshot is gone.** `components.cif.gz` (wwPDB 2026-08-22) and the
  derived `ccd_store.pkl` were in a scratch directory that has been cleaned. Step
  1 needs a fresh download, and a newer release may not reproduce bit-identically.
- **Two glue steps were never scripted.** `missing_ids.json` (referenced minus
  already-present components) and `coords_changed_vs_ccd.json` (records whose
  `model_Cartn` moved) were computed inline. The JSON files survive, so the chain
  runs — but neither can be regenerated against a different CCD release.
- **RDKit discards some stereo on re-reading.** `5YI` has three E/Z bonds in the
  string and RDKit reads back one. That is a reader limitation, not a defect in
  the data.
- **`A1ICR` and `A1JAD`** are polyoxometalate clusters whose SMILES no source
  represents in RDKit-sanitizable form.
- **`07G`** reports `generated_geometry_reproduces_smiles_stereo = NO` — the
  embedded conformer does not reproduce the SMILES stereo. Uninvestigated.
- The database mixes February-era and August-era CCD definitions: carried-over
  records were preserved rather than regenerated, so their non-stereo fields
  (names, formulae, charges) predate ~7,400 upstream revisions.
