랜덤 recycle + CUDA graph

CPU에서 recycle 수를 샘플링하고 해당 횟수의 미리 캡처한 graph를 선택합니다. Python의 랜덤 분기를 단일 graph 안에 캡처하면 replay마다 바뀌지 않습니다. R1~R4 graph 모두 동일한 parameter gradient 버퍼에 누적하고 optimizer는 그 버퍼를 읽습니다. 캡처 이후 grad 주소를 교체하면 안 됩니다. 각각 독립된 graph pool을 썼으며 shape bucket별 graph 준비와 메모리 비용은 별도 관리가 필요합니다.

PF16 단일 GPU에서 2→3→4→1→3→4→1→2 선택을 검증했습니다. Optimizer 전후 loss가 일반 실행과 일치하고 최대 gradient 상대 L2 오차 0.000105841. RNG 상태를 맞춘 비교이므로 dropout/MSA 난수 소비도 포함합니다. 현재 실행 중인 DDP 학습이나 changing-batch input staging에 적용한 결과는 아닙니다.

수정 내용

  • B7 컴파일 캐시·설정 파일 읽기·occupancy·shared-memory 설정을 장치/설정별로 재사용.
  • TMA 고정 메타데이터 검사를 캐시하고, 한 native op 안에서 검증한 CUDA context를 재사용. 실제 tensor 주소는 매번 읽음.
  • 고정 ABI의 필드 해석·정렬·패딩을 재사용하고 값과 포인터만 갱신.
  • 호스트 인자 저장 공간을 스레드별로 안전하게 재사용. 살아 있는 포장 객체끼리는 메모리를 공유하지 않음.
  • Activation과 gradient workspace는 각 호출이 소유하며 GPU 메모리 재사용은 PyTorch allocator가 담당. CUDA 계산 소스·융합·타일 설정은 변경하지 않음.

B7 backward 계획 생성20회는 worker cProfile에서 약25ms → 3.26ms. Warm 경로 compile-cache 호출은0회입니다. 이는 계측 하의 시간이며 일반 실행의 절감량과 동일하지 않습니다.
